# PROTOTYPE
> 역할: 프로토타입 목표/확정표/진행도를 관리하는 실행 계획 문서입니다.

- 마지막 갱신: `2026-02-20`
- 상태: `구현 준비 완료`

## 1) 목표

- 5스테이지까지 핵심 사이클(전투 -> 보상 -> 정비 -> 다음 스테이지) 플레이 가능 상태 달성
- 1차 플레이테스트에서 재미 검증이 가능한 최소 기능 완성
- 데이터 기반 효과 시스템(JSON + op DSL + ActionQueue + EventBus + Localization 바인딩) 기반 구현

## 2) 범위

- 포함:
  - 전투(`1:N`, 드래그 타겟팅, 카드/AP/주사위 해결)
  - 보상 화면(3택1+스킵, 희귀도 보정, 엘리트 유물 1개 제시)
  - 정비(고정 회복 결과 표시 후 다음 스테이지 진행)
  - 저장(스테이지 시작 시점 저장)
  - 효과 시스템 코어(ActionQueue/Stack + TCE Pre/Post + op DSL v0)
  - 표시 시스템(Localization 키/템플릿/런타임 바인딩)
- 제외:
  - 골드/상점/골드 보상
  - 강화/단련 시스템
  - 보스 항복 비활성 문구/토스트
  - `무조건 항복` 카드

## 3) 확정표 (P0)

| 항목 | 값 | 상태 |
|---|---|---|
| 전투 구도 | `1:N` | 확정 |
| 동시 적 수 상한 | `N max = 3` | 확정 |
| 적 액션 해결 순서 | 좌->우 순차 해결 | 확정 |
| 타겟팅 | 드래그 기반(슬더스형) | 확정 |
| 드래그 하이라이트 | 유효 타겟만 강조 | 확정 |
| 드래그 실패 처리 | 행동 취소 + 카드 원위치(추가 토스트 없음) | 확정 |
| 승리 조건 | 현재 전투의 모든 적 처치 | 확정 |
| 기본 핸드/AP | 5장 / 3 | 확정 |
| 턴 드로우 | 턴 시작 시 새로 5장 | 확정 |
| 덱 고갈 처리 | 버림 더미 셔플 후 재구성 | 확정 |
| 턴 종료 순서 | 미사용 플레이어 주사위 소멸 -> 적 주사위 피해 처리 -> 방어도 소멸 -> intents 전이 | 확정 |
| 방어도 소멸 타이밍 | `턴 종료 시 적 주사위 피해 처리`가 끝난 뒤 | 확정 |
| 정비 회복 | 최대 체력 40%(내림) | 확정 |
| 정비 UX | 회복 결과 표시 후 즉시 진행 | 확정 |
| 명예 시작/상한 | 2 / 2 | 확정 |
| 명예 회복 수단 | 없음(프로토타입) | 확정 |
| 보상 카드 수 | 3장 제시 -> 1장 선택 또는 스킵 | 확정 |
| 보상 종료 처리 | 미수령 보상은 폐기 | 확정 |
| 카드 보상 중복 | 보상 1묶음(3장) 내부 중복 금지 | 확정 |
| 희귀도 분포 | 기본 60/37/3, 엘리트 50/40/10, 보스 0/0/100 | 확정 |
| 희귀도 오프셋 | 런 시작 -5, Common 노출 +1, Rare 노출 시 -5 리셋 | 확정 |
| 샘플링 실패 처리 | 카드풀 0번 인덱스 강제 노출 + 에러 로그 | 확정 |
| RNG 재현성 | seed 기반 + RNG 스트림 분리(combat/reward) | 확정 |
| 스테이지 수 | 총 5, 3스테이지 엘리트, 최종 보스 1회 | 확정 |
| 스테이지 진행 형태 | 완전 선형(분기 선택 UI 없음) | 확정 |
| 스테이지 전투 구성 | 스테이지 풀(적 구성 템플릿)에서 균등 랜덤 선택 | 확정 |
| 스테이지 매핑 | stage 1/2/4=normal, stage 3=elite, stage 5=boss(고정) | 확정 |
| 스테이지 템플릿 스키마 | `templateId`, `poolType`, `enemyIds[]` | 확정 |
| 스테이지 템플릿 재사용 | 동일 런 내 재사용 허용 | 확정 |
| 엘리트 선택 규칙 | 엘리트 풀 내 랜덤 선택 | 확정 |
| 일반 템플릿 최소 수량 | `4` | 확정 |
| 엘리트 템플릿 최소 수량 | `2` | 확정 |
| 보스 템플릿 수 | `1`(고정) | 확정 |
| 스테이지별 적 수 제한 | 별도 제한 없음(`N max = 3`만 적용) | 확정 |
| 콘텐츠 최소량 | 일반 적 5종, 엘리트 적 2종 | 확정 |
| 보스 패턴 단계 | 단일 패턴(페이즈 없음) | 확정 |
| 시작 덱 | `찌르기x5, 휘두르기x4, 결투사x1` | 확정 |
| 시작 카드 보상풀 제외 | 찌르기/휘두르기 제외, 결투사 포함 | 확정 |
| 저장 시점 | 매 스테이지 시작 시 | 확정 |
| 저장 payload 필드 | seed, stageIndex, stageTemplateId, hp, honor, deck, assets, rareOffset | 확정 |
| 적 데이터 최소 스펙 | enemyId, hp, intents(FSM), passiveIds | 확정 |
| 패시브 정의 방식 | passiveIds 분리 참조만 허용(인라인 금지) | 확정 |
| dice 스키마 | `{side}` 단일 필드만 허용 | 확정 |
| 카드 dicePolicy | 카드 단위 1개(생성 주사위 공통 적용) | 확정 |
| 트리거 표준 | event + phase(Pre/Post) + when + do(op[]) | 확정 |
| 로그 매체 | 콘솔 전용 | 확정 |
| 로그 출력 주기 | 전투 종료 요약 | 확정 |
| 로그 최소치 | seed, rareOffset, 승패, 턴 수, 액션/이벤트 요약 | 확정 |
| 카드 풀 최소 수량 | `Common 8 / Uncommon 12 / Rare 5` | 확정 |
| 노출 판정 | 대상 적 주사위 0개(빈보드형, 1:N 대상 기준) | 확정 |
| 유리/불리 규칙 | 프로토타입 포함, 굴림 1회당 1스택 소모, 턴 이월 | 확정 |
| 피해 타입 표준 | DamageKind = Clash / PlayerDirect / EnemyDice | 확정 |

## 10) 진행도

- [ ] 데이터 스키마 확정(`CardDef`, `EnemyDef`, `PassiveDef`, `Reward`, `Stage`)
- [ ] 전투 코어 구현(턴/행동/해결/승패 판정)
- [ ] 보상 샘플러 구현(희귀도/오프셋/중복 금지/실패 처리)
- [ ] 스테이지 진행 구현(5스테이지 루프, 엘리트/보스 분기)
- [ ] 저장/불러오기 구현(스테이지 시작 저장)
- [ ] 플레이테스트용 로그 수집 연결
- [ ] ActionQueue/Stack(`addToTop`/`addToBottom`)
- [ ] EventBus(Pre/Post) + 결정적 트리거 순서(`priority + id`)
- [ ] Effect Interpreter(op DSL v0) + JSON 로딩/검증(unknown op/condition 탐지)
- [ ] RNG 결정성(스트림 분리) + 최소 로그(seed, 액션/이벤트 트레이스 요약)
- [ ] Unity Localization 바인딩(카드/패시브/키워드) + 템플릿 변수 누락 검증

## 11) DoD (Definition of Done)

- 5스테이지를 끊김 없이 플레이 가능
- 전투/보상/정비/저장이 문서 규칙과 일치
- 치명 오류(진행 불가, 저장 불능, 보상 생성 실패 루프) 없음
- 최소 로그(seed, rareOffset, 승패, 턴 수, 액션/이벤트 요약) 수집 가능
- 효과/표시 정합성:
  - 카드/패시브 수치 변경 시 텍스트가 동일 소스(stats/ctx) 바인딩으로 자동 반영
  - 누락 변수는 런타임 에러 로그로 탐지되어 불일치가 구조적으로 방지됨

## 14) 효과/표시 구현 기준 요약

- 데이터(JSON)에는 텍스트 미저장(name/desc 금지)
- 카드/적/패시브 효과는 `triggers(TCE)` + `op DSL`로만 정의
- 트리거 표준: `event + phase(Pre/Post) + when + do + priority + enqueue`
- 상태 변화는 ActionQueue/Stack을 통해서만 발생(직접 상태 변경 금지)
- Pre는 수정/취소, Post는 반응/연쇄 enqueue 전용
- RNG는 `combatRng/rewardRng` 분리, seed 고정
- Localization 키:
  - `card.{id}.name`, `card.{id}.desc`
  - `enemy.{id}.name`, `passive.{id}.desc`
  - `keyword.{kw}.name`, `keyword.{kw}.desc`
- Smart String 변수 바인딩:
  - `stats`, `ctx` 기반
  - 누락 변수는 에러 로그 처리

## 15) 장비/피해타입 표준 메모

- `plate_armor`: 적 주사위 피해 -2
- `guard_stance`: 이번 턴 적 주사위 피해 -3
- `가죽 헬멧`: 적 주사위 피해가 5 이상이면 피해 -3
- 피해 타입 표준: `Clash / PlayerDirect / EnemyDice`
